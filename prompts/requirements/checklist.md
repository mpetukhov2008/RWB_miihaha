# Чек-лист самопроверки (Requirements)

Проверь ответ перед отправкой:

## Цели
- [ ] Перечислены цели продукта (чего хочет достичь заказчик).

## Роли
- [ ] Каждая роль имеет уникальный ID вида `R-01` и осмысленное имя.
- [ ] Роли покрывают всех, кто взаимодействует с системой.

## Требования
- [ ] Каждый FR/NFR имеет уникальный ID: `FR-001`/`NFR-001` и т.д. (минимум 3 цифры).
- [ ] `type` соответствует ID: `FR-...` -> `FR`, `NFR-...` -> `NFR`.
- [ ] У каждого `must`-требования непустой `acceptance_criteria`.
- [ ] Есть хотя бы одно `must`-требование.
- [ ] `source` честно разделяет `customer` и `assumption`.
- [ ] `depends_on` ссылается только на существующие ID требований.

## Ограничения и риски
- [ ] Зафиксированы ограничения (технологии, сроки, нормативка).
- [ ] Риски имеют ID вида `RK-01` и описание влияния.

## Допущения
- [ ] Все домыслы вынесены в `assumptions`, а не в требования.

## Вопросы
- [ ] Не более 5 вопросов всего, не более 2 `blocking`.
- [ ] `blocking` только если ответ меняет архитектуру/безопасность/UX.
- [ ] У каждого `blocking`-вопроса есть `options` и `default_if_unanswered`.
- [ ] Вопросы с `severity=important/minor` не блокируют пайплайн.

## Формат
- [ ] Ответ — ТОЛЬКО JSON по схеме, без markdown-обёрток и пояснений.
