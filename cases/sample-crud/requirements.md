# Мини-кейс: CRUD-приложение (проверка универсальности)

## Контекст

Небольшое внутреннее приложение для ведения списка задач. Пользователь может
создавать, просматривать, редактировать и удалять задачи. Доступ — только
для авторизованных сотрудников. Хранение — реляционная БД.

## Цели

1. Вести список задач с приоритетами и статусами.
2. Просматривать задачи по фильтрам (статус, приоритет).
3. Аудит изменений задач.

## Роли

- **Сотрудник** — создаёт и редактирует задачи.
- **Администратор** — управляет справочниками (статусы, приоритеты).

## Функциональные требования

### FR-001: Создание задачи
Сотрудник создаёт задачу: заголовок, описание, приоритет, исполнитель.

Критерии приёмки:
- без заголовка задача не сохраняется;
- после сохранения задача видна в списке.

### FR-002: Редактирование задачи
Сотрудник редактирует поля задачи и меняет статус.

Критерии приёмки:
- изменения сохраняются с отметкой «кем и когда изменено».

### FR-003: Просмотр и фильтрация
Список задач фильтруется по статусу и приоритету.

Критерии приёмки:
- фильтры применяются без перезагрузки страницы.

### FR-004: Удаление задачи
Задача удаляется (soft-delete) администратором.

Критерии приёмки:
- удалённая задача не видна в обычном списке;
- в аудите остаётся запись об удалении.

## Нефункциональные требования

### NFR-001: Аутентификация
Все операции доступны только авторизованным пользователям.

## Ограничения

- Простой CRUD без сложной бизнес-логики.
- Один сервис, одна БД.

## Риски

- RK-01: Конфликты при параллельном редактировании.

## Допущения

- Обычный рабочий день, нагрузка низкая.

## Открытые вопросы

- Q-001 (important): Нужен ли экспорт списка в CSV? По умолчанию: нет.
