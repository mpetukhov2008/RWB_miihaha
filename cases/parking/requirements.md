# Парковочный помощник — бизнес-требования

## Контекст

Город запускает сервис платных парковок. Водитель паркуется в платной зоне,
оплачивает время через мобильное приложение, получает уведомления о статусе
сессии и может посмотреть историю своих парковок. Оплата на этапе MVP —
mock (имитация), реальная платёжная интеграция — позже.

## Цели

1. Дать водителю возможность быстро начать и завершить парковочную сессию.
2. Автоматически фиксировать тариф и длительность сессии.
3. Информировать водителя о начале, окончании и превышении времени.
4. Дать админу панель для управления зонами, тарифами и сессиями.

## Роли

- **Водитель** — оплачивает парковку, управляет сессией, смотрит историю.
- **Администратор** — управляет платными зонами, тарифами, просматривает сессии.

## Функциональные требования

### FR-001: Определение платной зоны
Приложение определяет, находится ли водитель в платной зоне (по геолокации),
и показывает тариф зоны до начала сессии.

Критерии приёмки:
- если водитель вне платной зоны — показывается сообщение «Вне платной зоны»;
- если внутри — показывается название зоны, тариф и кнопка «Начать сессию».

### FR-002: Активная парковочная сессия
Водитель может начать сессию в платной зоне. Система фиксирует время начала,
зону и тариф. Сессия считается активной, пока водитель её не завершит.

Критерии приёмки:
- после старта сессии приложение показывает таймер и текущую стоимость;
- повторный старт в той же зоне невозможен, пока активна сессия;
- завершение сессии фиксирует время окончания и итоговую стоимость.

### FR-003: Уведомления
Водитель получает уведомления: о старте сессии, за N минут до окончания
оплаченного времени, о превышении времени.

Критерии приёмки:
- уведомление о старте приходит сразу после начала сессии;
- уведомление о скором окончании приходит за 5 минут;
- уведомление о превышении приходит сразу после истечения времени.

### FR-004: История парковок
Водитель может посмотреть историю своих сессий: дата, зона, длительность,
стоимость, статус.

Критерии приёмки:
- история отображается списком, отсортированным по дате начала (новые сверху);
- каждая запись содержит зону, длительность, стоимость и статус.

### FR-005: Mock-оплата
Оплата на MVP имитируется: при старте сессии «списывается» фиксированная
сумма, при завершении — пересчитывается по факту. Реальная платёжная
интеграция не входит в MVP.

Критерии приёмки:
- при старте сессии создаётся платёжный слёб в статусе `pending`;
- при завершении сессии статус меняется на `paid` с итоговой суммой.

### FR-006: Admin-панель
Администратор управляет платными зонами и тарифами, просматривает активные
сессии и историю.

Критерии приёмки:
- админ может создавать/редактировать зону с тарифом;
- админ видит список активных сессий и историю по зоне.

## Нефункциональные требования

### NFR-001: Время отклика
API отвечает не дольше 300 мс в 95% запросов.

### NFR-002: Безопасность
Доступ к админ-панели только для роли администратора; все операции
аутентифицированы.

## Ограничения

- MVP без реальной оплаты (mock).
- Мобильное приложение — Angular (версия зафиксирована в answers).
- Локальная корпоративная модель без доступа в интернет.

## Риски

- RK-01: Геолокация неточна в плотной застройке — водитель может получить
  неверное определение зоны.
- RK-02: Таймеры уведомлений чувствительны к фону приложения — уведомления
  могут задерживаться.

## Допущения

- Водитель даёт согласие на геолокацию.
- Одна активная сессия на водителя.
- Тарифы задаются админом вручную (без динамики).

  По умолчанию: 20.1.6 (зафиксировано по PDF).
- Q-002 (important): Нужна ли поддержка нескольких парковочных зон в одной сессии?
  Варианты: да/нет. По умолчанию: нет.
