# Правила для агентов-генераторов

Этот файл — обязательный контракт для любого агента, который генерирует код
или артефакты (LLM-агенты пайплайна и ИИ-помощники).

## 1. Файлы-контракты — главный закон
- Общение между этапами — только через файлы-контракты: `schemas/*.schema.json`
  и артефакты в `generated/<case>/`.
- Никаких устных договорённостей в тексте промптов. Изменение схемы = merge
  request с пометкой для остальных потребителей схемы.

## 2. Схема важнее промпта
- Ответ LLM валидируется схемой (`schemas/*.schema.json` и Pydantic-модели).
- Ошибка валидации → retry с текстом ошибки, а НЕ «добавить правил в промпт».

## 3. Модель ничего не запускает
- Сборка, тесты, сканеры, запись файлов — только детерминированный Python.
- LLM возвращает JSON; всё остальное делает код пайплайна.

## 4. Всё на диск, воспроизводимо
- Результат прогона — в `generated/<case>/`, состояние и метрики — там же.
- Прогон возобновляем: этапы со статусом done пропускаются.

## 5. Не выдумывай факты
- Всё, что не подтверждено заказчиком, — в `assumptions`, не в требования.
- В коде и шаблонах НЕ должно быть слов конкретного кейса («парковка», «зона»)
  — пайплайн универсален, кейс №2 запустят организаторы.

## 6. Секретов нет
- Только `.env.example` и CI variables. Ни одной строки с реальным ключом,
  паролем или URL прод-сервера.

## 7. Ручных правок сгенерированного кода нет
- Если что-то сломалось — чини шаблон (`templates/`), промпт или валидатор,
  а не сгенерированный файл.

## 8. Структура агента
- Каждый агент живёт в `pipeline/agents/NN_name/`:
  - `prompt.md` — системный промпт (роль, задача, что НЕ входит, правила,
    «верни ТОЛЬКО JSON по схеме», ссылка на чек-лист);
  - `schema.json` — JSON Schema артефакта;
  - `checklist.md` — чек-лист самопроверки модели.
- Версия промпта фиксируется в `state.json`.

## 9. Детерминизм где можно
- Всё, что выводимо из артефактов (OpenAPI из операций, DTO из OpenAPI,
  клиент API, docker-compose) — генерируется кодом, без LLM.

## 10. Один этап = один агент = один артефакт
- Не пиши несколько агентов в одном этапе и не смешивай ответственность.
