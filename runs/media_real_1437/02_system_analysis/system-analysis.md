# Системный анализ

## Границы системы
**Внутри:** Модуль распознавания и верификации фотографий (распознавание рекламного блока, оценка качества снимка, сверка с эталонным макетом), Модуль анализа видеопотока и детекции рекламного ролика (определение временных меток start_time, end_time), Модуль автоматической нарезки видео (вырезание 15-секундного фрагмента, формирование MP4 H.264), Модуль хранения и интеграции результатов (сохранение в S3, отправка статусов в Kafka и REST API), Мобильное приложение (Android/PWA) для загрузки исходных медиафайлов и запуска обработки, Backend-сервис (C#/.NET) для оркестрации обработки медиафайлов, Алгоритмы компьютерного зрения (OpenCV, PyTorch/TensorFlow) для анализа фото и видео, Инструменты обработки видео (FFmpeg) для нарезки и кодирования
**Снаружи:** Смежная система (принимает итоговые файлы в S3 и статусы выполнения через Kafka / REST API), S3-хранилище (внешний сервис хранения медиафайлов), Kafka (внешняя брокерная система для событий), REST API смежных систем (внешние интерфейсы для передачи статусов), Сотрудник технической службы (актор, производящий съемку и загрузку файлов)

## Роли и разрешения
- **Сотрудник технической службы**: Загружать исходные фото- и видеоматериалы в систему; Загружать эталонный фотомакет (JPEG/PNG) для верификации; Запускать обработку медиафайлов (автоматически или принудительно); Просматривать результаты обработки (статус, процент схожести, временные метки); Получать ссылки на итоговые медиафайлы в S3
- **Смежная система**: Получать итоговые медиафайлы из S3; Получать статусы выполнения обработки через Kafka; Получать статусы выполнения обработки через REST API; Получать ссылки на сохраненные файлы или их ID

## Сценарии использования
### US-001: Верификация фотоотчета по эталонному макету
**Актор:** Сотрудник технической службы
**Требования:** FR-001, FR-004, NFR-002
**Шаги:**
1. 1. Сотрудник загружает фото рекламной конструкции и эталонный фотомакет (JPEG/PNG) в мобильное приложение.
1. 2. Мобильное приложение передает файлы в backend-сервис.
1. 3. Модуль распознавания находит рекламный блок на фото.
1. 4. Модуль оценивает качество снимка (фокус, освещенность, отсутствие бликов/засветов).
1. 5. Модуль сверяет фото с эталонным макетом и вычисляет процент схожести.
1. 6. Система присваивает статус: «Соответствует макету», «Не соответствует» или «Низкое качество».
1. 7. При успешной проверке фото автоматически распределяется и привязывается к заявке.
1. 8. Итоговый файл сохраняется в S3.
1. 9. Статус «Выполнено» и ссылка на файл отправляются в Kafka и через REST API смежной системе.
**Результат:** Фото верифицировано, статус и процент схожести зафиксированы, файл сохранен в S3, смежная система уведомлена.

### US-002: Детекция рекламного ролика в видеопотоке
**Актор:** Сотрудник технической службы
**Требования:** FR-002, NFR-001
**Шаги:**
1. 1. Сотрудник загружает видеоролик длительностью 150–300 секунд и эталонный фотомакет в мобильное приложение.
1. 2. Мобильное приложение передает файлы в backend-сервис.
1. 3. Модуль анализа видеопотока извлекает кадры из видео.
1. 4. Алгоритмы компьютерного зрения анализируют кадры и определяют временные метки (start_time, end_time) появления искомого рекламного креатива.
1. 5. Система обрабатывает случаи с двумя разными роликами в разных блоках.
1. 6. Формируется отчет с временными метками появления креатива в исходном видео.
**Результат:** Определены точные временные метки появления рекламного ролика, сформирован отчет.

### US-003: Автоматическая нарезка 15-секундного рекламного ролика
**Актор:** Сотрудник технической службы
**Требования:** FR-003, FR-004, NFR-001
**Шаги:**
1. 1. На основе временных меток из US-002 модуль нарезки запускает FFmpeg.
1. 2. FFmpeg вырезает 15-секундный фрагмент из исходного видео с погрешностью не более 0,1 секунды.
1. 3. Формируется итоговый видеофайл в формате MP4 с кодеком H.264.
1. 4. Итоговый файл автоматически распределяется и привязывается к заявке.
1. 5. Файл сохраняется в S3.
1. 6. Статус «Выполнено» и ссылка на файл отправляются в Kafka и через REST API смежной системе.
**Результат:** 15-секундный рекламный ролик вырезан, сохранен в S3, привязан к заявке, смежная система уведомлена.

### US-004: Обработка нескольких вхождений ролика в видео
**Актор:** Сотрудник технической службы
**Требования:** FR-002, FR-003
**Шаги:**
1. 1. Модуль анализа обнаруживает несколько вхождений искомого ролика в 300-секундном видео.
1. 2. Для каждого вхождения определяются временные метки start_time и end_time.
1. 3. По умолчанию вырезаются все найденные целевые ролики (согласно default_if_unanswered Q-002).
1. 4. Для каждого вырезанного ролика формируется отдельный MP4-файл.
1. 5. Все файлы сохраняются в S3 и привязываются к заявке.
1. 6. Отчет содержит все временные метки всех вхождений.
**Результат:** Все вхождения ролика вырезаны, сохранены в S3, отчет содержит все временные метки.

### US-005: Принудительный запуск обработки
**Актор:** Сотрудник технической службы
**Требования:** FR-001, FR-002, FR-003
**Шаги:**
1. 1. Сотрудник вручную инициирует принудительный запуск обработки загруженных медиафайлов.
1. 2. Backend-сервис ставит задачу в очередь обработки.
1. 3. Обработка выполняется по сценариям US-001, US-002, US-003 в зависимости от типа файла.
1. 4. Результаты сохраняются и передаются смежной системе.
**Результат:** Обработка выполнена принудительно, результаты сохранены и переданы.

## Сущности
- **Заявка** — Бизнес-объект, к которому привязываются итоговые медиафайлы (фото и видео).
- **Эталонный макет** — Статический шаблон (JPEG/PNG), используемый как референс для верификации фото и детекции видео.
- **Фотоотчет** — Исходное фото рекламной конструкции, загруженное сотрудником для верификации.
- **Видеопоток** — Исходный видеоролик длительностью 150–300 секунд, содержащий один или несколько рекламных роликов.
- **Результат верификации фото** — Структура данных: процент схожести, статус («Соответствует макету», «Не соответствует», «Низкое качество»), ID заявки.
- **Отчет детекции видео** — Структура данных: временные метки (start_time, end_time) всех вхождений рекламного креатива в исходном видео.
- **Итоговый медиафайл** — Вырезанный 15-секундный ролик (MP4, H.264) или верифицированное фото, сохраненное в S3.
- **Событие обработки** — Тонкое событие Kafka / REST-ответ: статус «Выполнено», ссылка на файл или его ID, ID заявки.

## Допущения
- Хронометраж одного целевого рекламного ролика фиксирован и составляет 15 секунд.
- Сотрудник загружает исходные файлы после съемки в зоне со стабильным интернет-соединением для передачи тяжелых видео в S3/на бэкенд.
- Эталонный статический макет (JPEG/PNG) используется как единый референс и для фото, и для видео.
- По умолчанию вырезаются все найденные целевые ролики с указанием всех временных меток в отчете (default_if_unanswered Q-002).
- Ключевые элементы макета распознаваемы на протяжении ролика или фиксируются по стартовому/финальному кадру с отсечкой 15 секунд (default_if_unanswered Q-001).
- Обработка видеофайла длительностью 150 секунд должна завершаться не более чем за 20 минут.
- Точность распознавания фото и сопоставления с эталоном составляет не менее 95–97% тестовых случаев.
- Система должна поддерживать интеграцию в существующее мобильное приложение (Android на Kotlin или PWA на Angular).

## Открытые вопросы
- Q-001: Должен ли эталонный статический макет присутствовать на протяжении всех 15 секунд видеоролика (например, как пэкшот/водяной знак), или ролик динамический и макет появляется только в ключевых кадрах? (severity: important, impact: architecture)
- Q-002: Если в 300-секундном видео обнаружено несколько вхождений искомого ролика, нужно ли вырезать все вхождения или только первое? (severity: minor, impact: other)
