# Системный анализ

## Границы системы
**Внутри:** Модуль распознавания и верификации фотографий (распознавание рекламного блока, оценка качества снимка, сверка с эталонным макетом), Модуль анализа видеопотока и детекции рекламного ролика (поиск временных меток start_time/end_time), Модуль автоматической нарезки видео (вырезание 15-секундного фрагмента, формирование MP4/H.264), Модуль хранения и интеграции результатов (сохранение в S3, отправка статусов в Kafka и REST API), Мобильное приложение / PWA для загрузки медиафайлов и запуска обработки, Backend-сервис для оркестрации обработки медиафайлов, Хранение эталонных макетов (JPEG/PNG) и привязка результатов к заявкам
**Снаружи:** Сотрудник технической службы (актор, загружающий медиафайлы и запускающий обработку), Смежная система (принимает итоговые файлы в S3 и статусы через Kafka / REST API), S3-хранилище (внешний сервис хранения медиафайлов), Kafka (внешняя шина событий для передачи статусов), REST API смежной системы (внешний интерфейс для передачи статусов и ссылок), Сеть / интернет-соединение (канал передачи медиаданных)

## Роли и разрешения
- **Сотрудник технической службы**: Загружать фото и видео рекламных конструкций в систему; Загружать эталонный фотомакет (JPEG/PNG) для сверки; Запускать обработку медиафайлов (автоматически или принудительно); Получать результаты обработки (статус, процент схожести, временные метки); Просматривать привязку результатов к заявкам
- **Смежная система**: Получать итоговые медиафайлы из S3; Получать статусы выполнения через Kafka; Получать статусы выполнения и ссылки на файлы через REST API

## Сценарии использования
### US-001: Распознавание и верификация фотографии рекламной конструкции
**Актор:** Сотрудник технической службы
**Требования:** FR-001, FR-004, NFR-002
**Шаги:**
1. Сотрудник загружает фото рекламной конструкции (JPEG/PNG) и эталонный фотомакет в систему
1. Система находит рекламный блок на фотографии
1. Система оценивает качество снимка (фокус, освещенность, отсутствие бликов/засветов)
1. Система сверяет фотографию с эталонным макетом
1. Система вычисляет процент схожести и присваивает статус: «Соответствует макету», «Не соответствует» или «Низкое качество»
1. При успешной проверке система автоматически распределяет фото и привязывает его к заявке
1. Система сохраняет итоговый файл в S3 и отправляет статус «Выполнено» со ссылкой на файл в Kafka и через REST API
**Результат:** Фотография верифицирована, результат привязан к заявке, смежная система уведомлена о результате

### US-002: Анализ видеопотока и детекция рекламного ролика
**Актор:** Сотрудник технической службы
**Требования:** FR-002, NFR-001
**Шаги:**
1. Сотрудник загружает видеоролик длительностью 150–300 секунд и эталонный фотомакет в систему
1. Система анализирует кадры видеоролика
1. Система определяет точные временные метки (start_time, end_time) появления искомого рекламного креатива
1. Система формирует отчет с временными метками появления креатива в исходном видео
**Результат:** Сформирован отчет с временными метками появления рекламного креатива в исходном видео

### US-003: Автоматическая нарезка видео и сохранение результата
**Актор:** Сотрудник технической службы
**Требования:** FR-003, FR-004, NFR-001
**Шаги:**
1. Система получает временные метки (start_time, end_time) из модуля детекции ролика
1. Система вырезает 15-секундный рекламный ролик из общего видеофайла с погрешностью не более 0,1 секунды
1. Система формирует итоговый видеофайл (MP4, кодек H.264)
1. Система автоматически распределяет и привязывает итоговый файл к заявке
1. Система сохраняет итоговый файл в S3
1. Система отправляет статус «Выполнено» и ссылку на сохраненный файл (или его ID) в Kafka и через REST API
**Результат:** 15-секундный рекламный ролик вырезан, сохранен в S3, привязан к заявке, смежная система уведомлена

### US-004: Принудительный запуск обработки медиафайла
**Актор:** Сотрудник технической службы
**Требования:** FR-001, FR-002, FR-003, FR-004
**Шаги:**
1. Сотрудник загружает медиафайл (фото или видео) и эталонный макет
1. Сотрудник принудительно запускает обработку медиафайла
1. Система выполняет обработку в соответствии с типом медиафайла (фото — верификация, видео — детекция и нарезка)
1. Система сохраняет результат в S3 и уведомляет смежную систему
**Результат:** Медиафайл обработан принудительно, результат сохранен и передан смежной системе

## Сущности
- **Фотоотчет** — Фотография рекламной конструкции (JPEG/PNG), загруженная сотрудником для верификации
- **Эталонный макет** — Статический шаблон макета (JPEG/PNG), используемый как референс для сверки фото и видео
- **Видеоролик** — Исходный видеоролик длительностью 150–300 секунд, содержащий один или несколько рекламных блоков
- **Результат верификации фото** — Результат анализа фотографии: процент схожести, статус («Соответствует макету», «Не соответствует», «Низкое качество»)
- **Отчет детекции ролика** — Отчет с временными метками (start_time, end_time) появления рекламного креатива в исходном видео
- **Вырезанный ролик** — Итоговый 15-секундный видеофайл (MP4, H.264), вырезанный из исходного видео
- **Заявка** — Сущность, к которой привязываются результаты обработки медиафайлов
- **Событие статуса** — Событие, передаваемое в Kafka и через REST API: статус выполнения и ссылка на сохраненный файл (или его ID)

## Допущения
- Хронометраж одного целевого рекламного ролика фиксирован и составляет 15 секунд
- Сотрудник загружает исходные файлы после съемки в зоне со стабильным интернет-соединением для передачи тяжелых видео в S3/на бэкенд
- Эталонным референсом как для фото, так и для видео выступает статический шаблон макета (JPEG, PNG)
- Ключевые элементы макета распознаваемы на протяжении ролика или фиксируются по стартовому/финальному кадру с отсечкой 15 секунд (default_if_unanswered для Q-001)
- Вырезаются все найденные целевые ролики с указанием всех временных меток в отчете (default_if_unanswered для Q-002)
- Система поддерживает интеграцию в существующее мобильное приложение (ОС Android или PWA-режим в браузере)
- Обработка видеофайла длительностью 150 секунд выполняется не более чем за 20 минут

## Открытые вопросы
- Должен ли эталонный статический макет присутствовать на протяжении всех 15 секунд видеоролика (например, как пэкшот/водяной знак), или ролик динамический и макет появляется только в ключевых кадрах? (Q-001)
- Если в 300-секундном видео обнаружено несколько вхождений искомого ролика, нужно ли вырезать все вхождения или только первое? (Q-002)
